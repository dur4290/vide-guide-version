Ch4. 마크다운으로 AI와 문서 만들기

Chapter 4 ⏱ 약 20분

바로 코딩으로 들어가기 전에, 먼저 Claude Code와 함께 마크다운 문서를 만들어봅니다. 마크다운은 AI가 가장 잘 읽고 쓰는 문서 형식이라서, 파일 생성·수정·미리보기 흐름을 익히기에 좋습니다. 이 감각이 뒤에서 하는 바이브코딩의 기본기가 됩니다.

💡
이번 챕터에서 배우는 것
Claude에게 보고서 작성을 요청하면, 워크스페이스 안의 notes/reports/ 폴더에 마크다운 파일이 자동으로 저장되도록 연습합니다. 따로 저장 위치를 고르지 않아도 됩니다.

1. 마크다운이 뭔가요?

마크다운은 .md로 끝나는 텍스트 문서입니다. 그냥 글자만 있는 파일인데, 제목·목록·표·링크 같은 약속을 써서 보기 좋은 문서로 미리볼 수 있어요.

- 두 번째 항목

2. 워크스페이스 자동 저장 규칙 확인하기

1

워크스페이스 폴더 열기

Ch3에서 받은 학생 워크스페이스를 VSCode로 열어둔 상태에서 진행합니다. 왼쪽 파일 탐색기에서 CLAUDE.md를 확인하세요.

💡
CLAUDE.md에는 Claude가 따라야 할 작업 규칙이 들어 있습니다. 이 파일에 저장 위치 규칙을 적어두면 Claude가 새 파일을 알맞은 폴더에 만들 수 있어요.
2

마크다운 보고서 저장 위치

이 워크스페이스에서는 마크다운 보고서와 조사 문서를 notes/reports/ 폴더에 저장합니다. 

vibe-workspace/
└── notes/
    └── reports/
        └── 2026-05-18-ai-tools-report.md

날짜와 제목은 Claude가 알아서 붙입니다. 학생은 “어디에 저장할지”보다 “무엇을 만들지”에 집중하면 됩니다.

3. Plan Mode로 보고서 계획 세우기

먼저 바로 파일을 만들지 말고, 어떤 보고서를 만들지 계획부터 세워봅니다. Claude Code 입력창에서 Plan Mode를 켠 뒤 아래 문장을 그대로 입력하세요. 

내가 처음 써볼 AI 도구 3개를 비교하는 마크다운 보고서를 만들고 싶어.
먼저 어떤 구조로 조사하고 작성하면 좋을지 계획을 세워줘.
비교 표, 추천 사용자, 내가 써볼 만한 상황이 포함되면 좋겠어.
아직 파일은 만들지 말고 계획만 보여줘.
1

계획 검토하기

Claude가 보고서 목차와 조사 방향을 제안하면, 마음에 드는지 읽어보세요. 부족한 점이 있으면 “대학생이 읽기 쉽게 바꿔줘”처럼 추가 요청하면 됩니다.

4. 마크다운 파일 만들기

계획이 괜찮다면 이제 파일 생성을 요청합니다.

좋아. 이 계획대로 마크다운 보고서를 작성해줘.

조건:
- 파일은 워크스페이스 안의 notes/reports/ 폴더에 저장해줘.
- 파일명은 오늘 날짜와 주제가 보이게 정해줘.
- 제목, 요약, 비교 표, 추천 사용자, 내가 써볼 만한 상황을 포함해줘.
- 출처 링크를 넣는다면 공식 사이트 링크만 사용해줘.
- 초보자가 읽기 쉽게 너무 딱딱하지 않은 문장으로 써줘.
1

파일이 자동 저장됐는지 확인

VSCode 왼쪽 파일 탐색기에서 notes/reports/ 폴더를 열어보세요. 2026-05-18-ai-tools-report.md처럼 날짜가 들어간 파일이 생기면 성공입니다.

Claude에게 이렇게 말하세요: 
notes/reports 폴더가 없으면 만들고, 방금 작성한 마크다운 보고서를 그 안에 저장해줘.

5. VSCode에서 미리보기

마크다운 파일은 원본 텍스트로도 볼 수 있고, 보기 좋은 문서 형태로 미리볼 수도 있습니다.

1

미리보기 열기

  1. notes/reports/ 안의 .md 파일을 클릭하세요
  2. Ctrl + Shift + V를 누르세요
  3. 문서가 보기 좋은 형태로 열리면 성공입니다
💡
화면 오른쪽 위의 미리보기 아이콘을 눌러도 됩니다. 원본과 미리보기를 나란히 열면 수정 결과를 바로 확인할 수 있어요.

6. 문서 수정 요청하기

이제 파일을 사람이 직접 다 고치는 대신, Claude에게 개선을 요청해봅니다. 

방금 만든 보고서를 조금 수정해줘.

수정 방향:
- 첫 문단을 더 친절하게 바꿔줘.
- 표에 "추천 사용자" 열을 추가해줘.
- 마지막에 "내가 써볼 만한 도구 3개" 섹션을 추가해줘.
- 저장 위치는 그대로 notes/reports/ 안의 같은 파일로 해줘.
1

수정 결과 확인

미리보기 화면을 다시 확인하세요. 문장이 바뀌고 표에 새 열이 추가되었다면, Claude와 파일을 함께 수정하는 흐름을 익힌 겁니다.

7. 왜 이게 바이브코딩 준비인가요?

바이브코딩도 같은 흐름입니다. 먼저 목표를 말하고, Claude가 파일을 만들고, 우리는 결과를 확인하고, 다시 수정 요청을 합니다. 오늘은 코드 대신 문서로 연습했을 뿐이에요.

💡
오늘 익힌 흐름
계획 세우기 → 파일 생성 → 자동 저장 위치 확인 → 미리보기 → 수정 요청. 이 흐름을 이해하면 마지막 프로젝트에서 파일을 만들고 고치는 과정이 훨씬 덜 낯설어집니다.
